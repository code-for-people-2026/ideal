# 3.1 近邻闲置（Neighborhood Exchange）

> 当前状态：探索中的最小切口
>
> 这是“近邻闲置 → 近邻互助组 → 牛马互助平台”产品演进蓝图的第一阶段。

近邻闲置从一个小区里的低风险普通物品流转开始，让邻居完成一条足够短、能够在线下真实发生的路径：

> 发布 → 分享到邻居群 → 表达意向 → 约定线下交接 → 标记完成

这一阶段不是放弃近邻互助组或牛马互助平台，而是先验证最基础的邻里连接能否发生、能否重复。

## 当前边界

- 只服务一个小区。
- 只处理低风险普通物品。
- 线上只辅助展示、表达意向和约交接；交接在线下由居民自行完成。
- 不承诺交易担保、物流、支付、鉴定或纠纷仲裁。
- 技能、维修、街坊味等“闲置本领”只作为未来方向说明，不进入首期运行。

详细决议见[《从近邻互助组收缩到近邻闲置》](./product-decisions/2026-09-02-从近邻互助组收缩到近邻闲置.md)，领域语言见 [`CONTEXT.md`](./CONTEXT.md)。

## 客户体验原型（隔离探索分支）

分支 `codex/prototype-neighborhood-exchange` 保存一个**可丢弃 UI 原型**，用来回答：首期首页应该以“逛闲置”“办完流转”还是“邻里布告”为主心智？在选定方向前，三版 UI 不进入当前整理分支。

三个结构明显不同的方案位于同一路由：

- `?variant=A`：邻里货架——以发现物品为主。
- `?variant=B`：流转工作台——以推进状态为主。
- `?variant=C`：邻里小报——以一条条真实布告为主。

在该原型分支的 worktree 根目录运行：

```sh
python3 -m http.server 8000 --directory 3.1-neighborhood-exchange/prototype-customer
```

然后打开 <http://localhost:8000/?variant=A>。所有发布、分享、意向和交接操作只保存在当前页面内存中；刷新即重置。原型提交为 `287a5fa`，未推送远端。
