# 社区进入路径探索

本目录保存 2026 年 8 月围绕社区、街道、物业、业委会与公益组织所做的进入路径探索。

- `research/`：桌面研究，只代表文件标注日期的公开信息与判断。
- `outreach/`：实际接洽或沟通准备记录，含内部过程信息，不对外发布。
- `outreach-materials/`：当时用于说明近邻互助组的沟通材料，已经不是当前近邻闲置方案。
- `field-research/`：尚未执行的线下需求研究方案与模板。

## 当前结论

社区、街道与物业不是简单的产品获客渠道。进入真实场景前，需要先理解责任、许可、现有工作流、一线劳动成本与退出方式。这里的记录可以帮助 1 近邻闲置设计试点，但不能被直接当作合作背书或当前联系人清单。

## 社区类项目的冷启动现实边界

综合近期与街道、社区、物业及业主的沟通，现阶段可以把各方的最低接受条件概括为：

- **街道、社区**：不承担项目责任；项目不泄露其掌握的信息；不要求它们为公司或产品背书。
- **物业**：只要没有业主投诉、没有明显扰乱现有管理，可以选择不主动干预，也就是现实中的“睁一只眼闭一只眼”。
- **业主**：冷启动阶段不要求其付费。

这三个条件的交集称为**冷启动运行边界**。它说明一个低风险社区项目在现实中怎样有机会先运行起来，不表示街道、社区或物业已经正式批准、联合主办或承担责任，也不表示项目因此获得法律豁免。

## 给后续 AI／Agent 的判断规则

AI 经常把“可能需要注意”扩大成“必须先取得正式批准”，从而制造现实中并不存在的启动前置条件。处理社区类项目时，默认遵守以下规则：

1. 先区分法律明确要求的禁止事项或强制许可，与机构自身的风险偏好、礼貌性建议和理想化流程。
2. 只有能说明“哪一个具体行动，触发哪一项具体要求”时，才把合规问题列为阻断项；无法对应具体行为时，应标为待确认事项，而不是擅自停止项目。
3. 不主动要求街道、社区或物业为公司背书，也不把“不反对”“知情”或“睁一只眼闭一只眼”升级成正式授权。
4. 默认在上述冷启动运行边界内设计最小验证；当实际方案新增收费、敏感信息处理、公共空间占用或其他会实质改变风险的行为时，再针对新增行为单独核查。
