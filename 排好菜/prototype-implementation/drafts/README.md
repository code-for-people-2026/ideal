# 排好菜工程画布草稿

`engineering-board.html` 是工作包 C 的独立工程实现模型源稿，服务后续产品、前端、后端和测试团队。它不会替代客户体验原型；完成 A/B 契约校准后，内容已同步到正式的 `prototype-implementation/index.html`。

## 本地打开

文件不依赖构建工具、框架或新依赖，可以直接双击打开。为了避免部分浏览器限制本地文件行为，也可以从仓库根目录启动静态服务器：

```bash
python3 -m http.server 4173
```

然后访问：

```text
http://127.0.0.1:4173/排好菜/prototype-implementation/drafts/engineering-board.html
```

建议至少在 1280 × 720 视口验证一次。页面默认聚焦“实现总览”，正文不依赖把整张画布缩到 42%–45% 才能阅读。

## 四个视图

1. **实现总览**：v0.1 范围 / 非范围、系统上下文、组件分层和依赖方向。
2. **生成链路**：小程序端 → 应用门面 → `PlanGenerator` → `RuleEngine` → Repository / 存储的调用轨迹，以及菜品不足、规则冲突、存储失败、版本冲突四个失败分支。
3. **数据与接口**：`Dish`、`DishSelection`、`Meal`、`WeekPlan`、`SavedPlan`、`RuleEvaluation` 的关系、关键不变量和应用接口草案。
4. **异常与验收**：恢复保证、生成 / 换菜 / 保存 / 复制测试矩阵、建议证据位置和待决未知项。

画布中的数据源、性能、约束满足率、持久化结果和测试状态均标为 **Mock** 或 **待验证 / 待运行**，不表示真实后端、云数据库或运行指标已经存在。

## 交互与无障碍

- 顶部四个定位按钮可以聚焦对应视图；聚焦区域会避开固定工具栏。
- 在画布空白处按住并拖动可以平移；滚轮围绕指针缩放。
- 右下角提供缩小、放大和适配全局按钮；当前缩放比例通过 `aria-live` 更新。
- 键盘可以依次 Tab 到四个定位按钮和四个语义 `<section>`；视图获得焦点时自动进入可读缩放。
- `Alt+1` 至 `Alt+4` 可直接定位四个视图；`Enter` / 空格可重新聚焦当前视图，`Esc` 适配全局。
- 页面提供跳转链接、可见焦点、语义标题、表格标题和区域标签；主要信息均为可检查 DOM，不依赖截图或整页图片。

## 集成注意事项

- 当前文件已按工作包 A 的架构 / 数据契约和工作包 B 的流程 / 验收文档统一术语、错误码与证据路径。
- 领域依赖方向保持为：UI 与页面状态 → `ApplicationFacade` → `PlanGenerator` / `RuleEngine` → Repository 接口；具体存储适配器从外部注入。
- `PlanGenerator` 产出的完整候选经规则校验后形成 `EDITING` 活动计划；`confirmPlan` 进入只读 `CONFIRMED`，`savePlan` 才产生历史快照。
- `swapDish` 和 `selectDish` 的关键保证是只改变目标餐位；`copyPlan` 必须产生新 id、新目标周和 `EDITING / version 1`，不能继承旧版本。
- Mock Repository 与未来真实适配器共享契约。确定本地缓存、云数据库或 HTTP API 之前，不要把存储字段写进领域对象。
- 正式画布已复用本稿的暖白、砖红、深绿视觉令牌和原生拖动 / 缩放逻辑，没有引入第二套框架或构建链。
