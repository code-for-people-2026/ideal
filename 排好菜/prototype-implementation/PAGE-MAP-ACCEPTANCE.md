# 页面地图重做验收标准

## 目标

页面地图是给开发团队点击探索的“手机页面流程图”，不是需求文档、领域模型或 Issue 看板。它必须在一张可拖动、可缩放的画布上，用真实手机页面说明四个一级功能各自如何完成任务。

## 一票否决项

- 任何流程节点使用横向文档卡、表格、审计面板或文字说明代替手机页面。
- 手机页面没有稳定的设备比例、顶部状态栏、应用标题栏和底部导航，无法一眼识别为小程序。
- 把用户反馈、验收结论、领域术语解释或开发任务直接写进产品页面。
- 用与运行原型不一致的菜品数量、状态或能力伪装成“已实现”。
- 四条线重复实现同一个业务动作，且没有明确的数据交接。
- 只画静态图片，顶部功能筛选、单页面聚焦、缩放、适配或主要页面交互不可用。

## 画布与手机页面标准

- 保留 Kith/排好菜既有的暖灰画布、白色画板、顶部工具栏、拖动、滚轮缩放、适配和单画板聚焦。
- 每个流程节点必须是 `390 × 844` 左右比例的独立手机画板；允许按画布统一等比缩放，不允许压扁或拉宽。
- 复用现有 `public/assets/iphone/Bezel.png` 和 `public/assets/status/ios-status-icons.svg`，以及客户原型的米白、砖红、深绿、浅金视觉令牌。
- 手机内至少包含：状态栏、页面标题、真实内容区、主要按钮或状态、四项底部导航。弹窗或抽屉可以叠加在对应手机内。
- “全部”视图用于看四条线；点击某条功能线后该行手机在常见桌面视口下可读；点击单手机后以接近 1:1 的比例居中。
- 画布上的非手机文字只允许：功能线名称、一句目标、步骤编号、箭头交接标签、`已实现/计划中` 状态。不得出现长段审计说明。

## 四条功能线

### 1. 排菜单

独占 `WeekPlan` 的生成和修改，至少包含四个手机画板：

1. 选择上周/本周/下周并从空状态生成。
2. 查看五天十餐的菜单结果。
3. 点选一道菜后“换一道”或“自己选”。
4. 确认并保存本周菜单。

### 2. 菜品库

独占 `DishCatalog` 的浏览和菜品选择，至少包含三个手机画板：

1. 搜索、分类筛选和查看菜品列表。
2. 查看菜品详情。
3. 从同类候选中选中菜品，并通过箭头标明“返回排菜单替换当前菜”。

菜品新增、编辑、停用如果仍未实现，必须用虚线手机画板标成“计划中”，不能用文档缺口卡代替。

### 3. 历史

独占 `SavedPlan` 的检索和复用，至少包含三个手机画板：

1. 按周查看已保存菜单列表。
2. 展开完整十餐详情。
3. 确认复制到下一周，并通过箭头标明“生成草稿后交回排菜单”。

历史页不能直接编辑菜品。

### 4. 我的

独占 `HouseholdRule` 和个人设置，至少包含三个手机画板：

1. 我的首页与家庭规则摘要。
2. 编辑人数、忌口和菜单偏好。
3. 保存规则，并通过箭头标明“下次生成时由排菜单读取”。

规则编辑如果尚未进入运行原型，手机画板必须标为“计划中”，但仍要呈现目标手机交互。

## 功能边界验收

- 排菜单产出 `WeekPlan`；菜品库返回 `Dish`；历史返回复制后的 `WeekPlan draft`；我的提供 `HouseholdRule`。
- 跨线交接只用带动词和数据名的箭头表达，例如“返回 Dish”“复制为 draft”“读取 HouseholdRule”。
- 同一个手机页面不能在两条线上重复出现；需要引用时使用交接箭头，不复制页面。
- 每条线必须有明确的起点、完成态和独立用户价值。
- 已保存菜单只读；复制必须创建新草稿，不能把历史记录重新变为可编辑状态，也不能覆盖非空目标周。
- 菜品库手选只返回 `Dish`，真正写入当前菜单仍由排菜单完成。

## 交互验收

- 顶部“全部 / 排菜单 / 菜品库 / 历史 / 我的”均可点击，并正确更新 `aria-pressed`。
- 点击每个手机画板可聚焦；聚焦后页面文字和主要按钮可读。
- 拖动画布、滚轮缩放、“缩小 / 放大 / 适配”均可用。
- 主要页面内至少提供可见状态切换示例：周切换、菜品选择、历史详情展开、规则选项。
- 一级导航固定为“项目入口 / 运行原型 / 页面地图 / 实现说明 / 客户原型”，每个名称只对应一个目的地；功能线筛选放在独立的二级工具栏。

## 最终质量门槛

- 1280 × 720 和当前应用内浏览器视口均无工具栏遮挡、画布裁切或横向页面变形。
- 页面控制台无 warning/error；键盘焦点清晰；`prefers-reduced-motion` 可用。
- `npm test`、`npm run build:pages`、仓库级 `scripts/build-pages-site.sh` 和 `git diff --check` 全部通过。
- 最终必须保存：全部视图、四条线聚焦、单手机聚焦截图，并与已确认的 Kith/排好菜画布视觉并排检查。
- 主 agent 按本文件逐条验收；出现任一一票否决项，必须返工后再交付。
