# 微信群闲置整理原型

该原型将两个指定微信群最近七天的闲置发布整理成卡片：有图物品优先，无图发布简略列在后面，点击后查看发布人昵称、头像、照片、报价及成交证据。

这是对既有聊天记录的独立展示实验，所属产品上下文见 [近邻闲置](../README.md) 与 [领域语境](../CONTEXT.md)。它尚未实现居民自主发布、表达意向和交接约定的完整流程，也不改变近邻闲置首期的产品范围。

## 当前行为

- `/baolong` 与 `/luanshan` 分别展示对应群的物品、发布人和统计，无跨群导航。
- 页面、浏览器及分享预览标题使用完整群名。
- 两群使用不同密码；带 `#password=...` 的群链接可以自动验证，页面在发起验证前清除片段。普通链接仍提供密码输入框。
- 物品接口与照片、头像接口均校验群权限。一个群的密码不能访问另一个群的专属数据与媒体。
- 密码以 scrypt 哈希保存在服务器配置中，会话使用签名的 HttpOnly Cookie，有效期七天；更换群密码使旧会话失效。
- 登录频率限制保存在 Neon。数据加载短暂失败会重试，权限失效返回密码入口。

## 代码来源与私有输入

本目录迁入 2026-09-13 已部署原型的代码，来源项目提交为 `16a36b5`。当前导入只提交代码、环境变量模板和测试；原始微信数据库、整理后的真实数据、群图片、头像、访问密码、数据库连接、部署绑定及本机运行缓存均不进入 Git。

原有生产部署和每天北京时间 02:00 的本机更新任务继续在已有运行目录执行；此次代码入库不重新部署，不修改账号或重置密码。微信采集与图片解码由本机已安装的 `wechat-idle-sync` / `wechat-cli` 技能负责，运行环境配置不随此源码分发。

## 检出后构建与检查

需要 Node.js 22 与 npm，在本目录执行：

```sh
npm ci
npm test
npm run build
npm run dev
```

默认测试只使用代码内的合成记录和临时生成的测试密钥，无需微信、Neon、真实图片或生产密码。未配置本地数据与服务器凭据时，开发服务可以展示群密码入口；成功登录和物品展示需要下一节中的私有输入。

`dist/` 保留迁入时的三个页面源文件，实际 Vercel 公开输出目录是构建生成的 `public/`，只含 HTML、CSS、JS。群图片在 `dist/assets/` 作为函数的私有输入；`/assets/*.jpg` 不发布。

## 配置独立运行环境

1. 将 `.env.example` 复制为 `.env.local`，配置独立 Neon 数据库的 `DATABASE_URL`。
2. 执行 `node --env-file=.env.local scripts/setup-access.mjs`，生成本地两群密码、scrypt 哈希与会话密钥，并创建登录限流表。本地私有文件为 `.local/group-access.json`；已有文件会复用，日常更新不重置密码。
3. 从授权的本机采集流程取得 `data/items.json`、`data/people.json`、`data/metadata.json` 以及对应的 `dist/assets/*.jpg`。这些路径均已被 Git 忽略。
4. 执行 `npm run db:check` 校验文件、群归属与时间范围，再通过 `npm run db:import` 原子导入该环境的 Neon。
5. 在 Vercel 中将项目根目录指定为本目录，按 `.env.example` 配置服务器环境变量。通过 CLI 标准输入传入密钥，不把它们写进命令、源码或构建产物。

原型保留对 `situbite` 来源及“司徒比特”账号的校验，不能直接用另一个账号的数据替代。来源规则位于 [lib/snapshot.mjs](lib/snapshot.mjs)，输入文件与事务导入流程位于 [scripts/import-snapshot.mjs](scripts/import-snapshot.mjs)。

导入新的图片时先部署包含新图的受保护函数，随后事务导入 Neon；未被当前群快照引用的图片按设计返回 404。每日更新仍需逐条核对实际消息和图片，跨群核对材料只留本机，不写入另一个群的描述、备注或时间线。

## 集成验证

`npm run test:browser` 使用 `.env.local`、本地整理数据与 `.local/group-access.json`，会对所配置的数据库执行登录限流测试；应使用独立测试环境，不能为了运行测试导入真实聊天或复制生产凭据到仓库。浏览器验证当前使用本机 Microsoft Edge（Playwright `msedge` 通道）。

部署后可执行 `node scripts/verify-live.mjs --url <该环境的站点地址>`，检查匿名访问、自动密码链接、群间隔离、全部图片与发布人详情。Vercel 预览域名受平台保护时，可通过子进程环境变量 `IDLE_DEPLOYMENT_BYPASS` 传入该项目的自动化 bypass；它不替代群密码。

Vercel 使用 Standard Protection 限制历史部署和预览地址，生产群入口使用本站密码。当前原型依赖服务器鉴权，因此不加入仓库的 GitHub Pages 发布白名单，也不生成跨群公共索引。
