# 跨渠道 Agent 通信边界产品决议

> 状态：已确认方向，User Stories 与两份原型已同步
> 日期：2026-08-10

近邻互助组不建设普通用户之间的泛社交网络，但会在小程序内为每一次具体亲历、服务需求或履约过程建立受限群聊。该房间同时容纳消费者、消费者 Agent、服务者、服务者 Agent 和近邻系统 Agent，并以同一个事项、授权和审计链连接服务号、小程序与后台 Agent 协作。

## 通信面

| 关系 | 主要渠道 | 平台责任 |
| --- | --- | --- |
| 无具体服务事项的人 ↔ 人 | 微信或其他既有社交平台 | 提供可携带的亲历卡、授权摘要和下一步入口；不托管泛社交 |
| 用户 ↔ 自己的 Agent | 已认证服务号；服务事项房间 | 持续私有对话、轻量任务与受微信规则限制的主动触达；经授权后代表用户入房协作 |
| 服务者及其 Agent ↔ 消费者及其 Agent | 近邻互助组小程序的服务事项房间 | 显示每个发言主体、Agent 归属、数据范围、证据、授权和真人确认边界 |
| 服务者 Agent ↔ 消费者 Agent | 服务事项房间或平台后台 | 传递获授权的消息、证据引用、进度、确认请求和撤销事件 |
| 近邻系统 Agent ↔ 房间所有参与者 | 近邻互助组小程序的服务事项房间 | 标明事项来源、权限与责任边界，协调交接和确认；不代表任一真人或其 Agent |

## 统一边界

- 每个跨渠道流转都属于一个稳定的事项 ID，不使用 OpenID、小程序 session 或聊天 room ID 作为业务主键。
- 每次传递都记录发送主体、接收主体、Agent 所属用户、授权来源、最小数据范围和幂等键。
- Agent 的协作结果不自动等于所属真人的最终承诺；报价、接单、支付、变更和其他高风险动作需要显式确认。
- 房间参与者只能看到当前服务事项的授权摘要和房间消息，不得看到任何一方的其他服务号或小程序会话。
- 服务号的客服消息、订阅/模板和群发能力均受微信规则约束；“主动触达更好”不等于可以无条件推送。

## 对现有资料的影响

现有“四方同屏聊天室”修正为默认五方服务事项房间：消费者、消费者 Agent、服务者、服务者 Agent 和近邻系统 Agent 都是可辨认的参与者。近邻系统 Agent 负责房间级规则和协作秩序，不得冒充消费者 Agent，也不得替任何真人或其 Agent 作出承诺。
