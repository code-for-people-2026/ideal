实现总览

锁定 v0.1 的交付边界，让依赖只向领域内侧收敛。

范围基线 · 契约已对齐
工程模型 v0.1实现基线 · 2026-08-24

本轮实现

  • 生成周一至周五、午晚餐共 10 餐
  • 逐道换菜 / 手选，仅修改选中餐位
  • 确认保存、历史读取与复制后再调整
  • 本地 Mock 数据和可替换 Repository

明确不做

  • 登录、家庭协作与权限模型
  • 云同步、真实推荐和跨设备冲突合并
  • 采购清单、库存、营养与成本计算
  • 后台管理、埋点报表和 KPI 看板

组件分层与职责

UI 与页面状态收集周起始日、选择餐位、展示草稿 / 警告 / 重试，不直接改存储。
PlanningApplication统一 generatePlan / swapDish / selectDish / confirmPlan / savePlan / copyPlan，编排事务与错误。
PlanGenerator组装完整候选并交由规则校验；成功后形成 EDITING 计划。
RuleEngine返回 RuleEvaluation；硬违规阻断，软违规随成功结果返回。
出站端口DishCatalogPort / WeekPlanRepository / SavedPlanRepository 隔离菜品、活动计划和历史快照。
Storage Adapterv0.1 先接 Mock；未来本地或远端实现必须保持同一契约。
依赖规则： UI → 应用门面 → 领域服务 → Repository 接口；具体适配器从外部注入。生成失败不得留下半份已保存菜单。

03

数据与接口

领域对象表达业务不变量；应用接口只暴露用例结果与可处理错误。

契约草案 · 待实现验证

领域对象关系

WeekPlan

id, weekStartEDITING | CONFIRMED | SAVEDversion, meals[10]
1 包含→10

Meal

id, date, slotdishes[5]slot: LUNCH | DINNER
1 包含→5

DishSelection → Dish

position, expectedKinddish: DishSnapshotMEAT | VEGETABLE | SOUP
Dish
id · name · kind · mainIngredientKeys[] · status
RuleEvaluation
hardViolations[] · softViolations[] · isHardValid
SavedPlan
不可变历史快照 · sourcePlanVersion · savedAt

关键不变量

  1. weekStart 为周一；只包含周一至周五。
  2. date + slot 唯一，恰好 10 个 Meal。
  3. 每餐恰好 2 荤、2 素、1 汤。
  4. DishSelection 只能引用 CONFIRMED Dish，kind 与位置匹配。
  5. 换菜只替换目标 mealId + position；其他 49 位不变。
  6. 所有成功写命令 version +1；过期 expectedVersion 拒绝覆盖。

应用接口签名

  • generatePlan(input: GeneratePlanInput): Promise<AppResult<PlanMutationResult>>生成并插入 EDITING / version 1 活动计划。
  • swapDish(input: SwapDishInput): Promise<AppResult<PlanMutationResult>>自动选择同类有效候选，只改变目标位置。
  • selectDish(input: SelectDishInput): Promise<AppResult<PlanMutationResult>>手选候选；与换一道共享替换和整周校验。
  • confirmPlan(input: ConfirmPlanInput): Promise<AppResult<PlanMutationResult>>EDITING → CONFIRMED；完整重验后进入只读总览。
  • savePlan(input: SavePlanInput): Promise<AppResult<SavePlanOutput>>原子地产生 SAVED WeekPlan 与不可变 SavedPlan。
  • copyPlan(input: CopyPlanInput): Promise<AppResult<PlanMutationResult>>从历史快照创建新 ID、version 1 的 EDITING 计划。
  • DishCatalogPort.listConfirmed(): Promise<CatalogSnapshot>本次命令使用稳定 catalogVersion 的已确认菜品。
Mock 边界：草稿只约定 InMemory / Fixture Repository；是否使用本地缓存、云数据库或 HTTP API 均待验证。真实适配器不得把存储字段泄漏到领域对象。
04

异常与验收

失败先保护用户草稿和一致性；所有测试状态默认“待运行”。

证据清单 · 尚未跑数

异常恢复约定

错误系统保证用户恢复验收观察点
菜品不足不返回残缺 WeekPlan指出缺少类别，补菜或调整规则后重试10 餐 × 5 位仍为硬门槛
规则冲突硬冲突不降级为软提醒展示可行动的 violation，而非通用失败错误包含 ruleId / path / reason
存储失败EDITING / CONFIRMED 保留；SAVED 不提前出现同一 commandId 重试，避免重复记录失败前后持久化快照一致
版本冲突expectedVersion 不符即拒绝覆盖刷新当前版本；人工重做变化项旧版本写入返回 VersionConflict
