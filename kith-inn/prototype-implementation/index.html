Implementation reference · 总蓝图

一个产品，
桃子端与顾客端一起成立。

这里不删过程：工程师从两个角色分别进入，逐屏理解菜单、餐次、订单、配送和收款怎样连接。两套 iPhone 原型保留全部讲解状态，后续写 App 时按 User Story 对照。

最新实现口径产品决策与 User Story 是开发需求；迁入角色稿里的“长期订单”和“截图对账”保留为历史讨论页，P0 实现采用“桃子维护订餐约定”和“按订单手工标记收款”。
Role A · 经营者

桃子使用端

从菜品池、配送范围和周菜单，到发布餐次、查看订单、手动补单与收款标记，保留完整经营过程。

9 个讲解状态4 个 App 底部入口发布后菜单锁定
打开桃子端直接看订单
Role B · 顾客

顾客使用端

从微信群菜单卡片进入，查看午晚餐、提交订单、选择配送地址，再回到“我的订单”确认状态。

5 个讲解状态2 个 App 底部入口午晚餐可一起订
打开顾客端直接看订单
