# 排好菜运行原型：真实尺寸可读性审查

审查日期：2026-08-31

## 审查范围

覆盖首次准备 6 个步骤、排菜单首页、编辑、换菜、确认、历史、菜品库、菜品详情、添加菜、“我的”和隐私政策弹层。

目标：判断真实手机展示尺寸下的字号、说明文字数量和页面主次关系是否适合阅读。

## 总体结论

问题是全局性的，不只出现在排菜单首页。

- 手机画布以 `0.78` 比例展示。
- 大量源字号为 `10—12px`，最终可见字号约为 `7.8—9.4px`。
- 多数页面同时展示标题、解释、状态、统计和操作提示，放大字号后会进一步拥挤。
- 需要先删减默认状态下的说明，再统一提高字号；只做其中一项都不够。

## 优先改动

1. 增加 1:1 手机聚焦查看方式；工程画布不再强迫手机以 78% 显示。
2. 统一移动端字号下限：正文/控件 15—16px，辅助信息 13—14px，导航不低于 12px。
3. 默认状态只说明“当前结果”和“下一步”；规则解释只在异常、首次出现或用户主动查看时展示。
4. 准备完成页合并为一个结果卡、一条关键提醒和一组操作。
5. 编辑、确认和历史不再把完整五天十餐压在同一视野；保留表格关系，但一次聚焦 1—3 天并允许横向切换。
6. 菜品库列表只保留菜名和一个必要标签；频次、主料规则放入详情。

## 证据限制

本次依据当前桌面画布中的手机渲染、DOM 文本结构和计算字号进行审查。截图可以确认视觉密度和可见字号风险，但不能单独证明真实设备上的字体渲染、系统字号适配、屏幕阅读器或完整 WCAG 合规性。
