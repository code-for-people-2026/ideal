# 楼道收一收 · 物业沟通前痛点假设与访谈提纲

> 状态：内部访谈准备，不是对外宣传稿
>
> 更新：2026-08-31
>
> 原则：以下内容都是需要物业本人确认或推翻的假设。不要把“我们能做什么”当成“物业一定需要什么”，也不要为了证明项目合理而诱导对方同意。

## 一、已经知道的事实与尚不知道的事

### 已从居民、保洁和业委会视角确认的问题

- 居民在微信群反映卫生后，常得到管家快速回复“已经找人”，但没有后续追踪、结果查看和反馈入口。
- 保洁可能已经完成清洁，现场随后因宠物或人员活动再次变脏；一线人员缺少简单证据还原前后事实。
- 定向回收对部分保洁每月可能是数百元补充收入，通知不及时或现场规则不清会使这项收入流失。
- 业委会难以持续监督物业事项是否执行；“透明社区”使用率不高，尚未形成低门槛的居民触达入口。

### 不能替物业回答的问题

- 管家是否觉得转述消息麻烦，还是把快速回复视为展示服务形象的重要工作？
- 物业最在意的是居民满意、外包履约、人员调度、投诉升级、成本，还是没有这方面的明显痛点？
- 物业是否愿意把处理结果向居民和业委会呈现？如果不愿意，原因是操作成本、责任风险、数据解释，还是权责边界？
- 物业是否认可住户把自有可回收物定向交给保洁，以及这件事与保洁公司合同和公区管理是否冲突？
- “透明社区”没有形成使用习惯，主要卡在入口、功能、宣传、承接能力还是居民信任？

## 二、七组待验证假设

### 假设一：物业有“响应可见、结果不可见”的服务信誉问题

**可能价值**：完成时间和现场结果可以把“已经找人”变成可信的服务事实，减少居民重复追问和笼统指责。

**可能反证**：快速回复已经足以维持服务感知；物业不愿承担公开结果后的时限预期；多数事项本来就通过群聊解决，没有持续争议。

**要问：**

1. 管家回复“已经找人”之后，居民通常还会追问几次？什么情况下会升级成投诉？
2. 物业有没有遇到“实际做了但居民不认可”的情况？现在怎样证明？
3. 如果居民能看到完成时间和结果，物业认为最可能减少什么，又最担心增加什么？

### 假设二：物业需要更公平地判断保洁外包履约

**可能价值**：记录能区分“没打扫”“打扫后再次污染”“消息没有送达”和“现场没发现”，帮助物业与保洁公司依据事实沟通。

**可能反证**：物业已有巡检、打卡和主管机制；新增居民上报只是噪声；记录容易被机械地转成一线考核，反而破坏合作。

**要问：**

1. 物业现在如何验收保洁公司的工作？谁记录、记录到什么粒度？
2. 遇到业主与保洁说法不一致时，通常怎样处理？
3. 什么记录足以说明一次清洁完成？时间是否足够，哪些情况才需要照片？
4. 哪些数据绝不能脱离排班、再次污染和现场条件直接用于个人考核？

### 假设三：楼层与时段信息能帮助现场安排

**可能价值**：重复污染楼层、集中出纸箱时段等事实可以帮助物业调整巡查路线、宠物治理提示或人员安排。

**可能反证**：样本太少、随机性太强；物业排班由合同固定，无法调整；分析数据本身需要额外人员。

**要问：**

1. 哪些楼层、时段或问题最容易反复？现在凭经验还是有记录？
2. 即使知道规律，物业实际上能调整什么？
3. 多大频率、持续多久的数据才值得采取行动？

### 假设四：定向回收有助于保洁收入与稳定，但可能带来规则冲突

**可能价值**：住户主动定向交付可以让保洁获得更多真实补充收入，改善积极性和人员稳定。

**可能反证**：保洁公司合同不允许；公区物品权属不清；放置影响消防和卫生；不同保洁之间分配不公平。

**要问：**

1. 物业和保洁公司目前如何看待保洁收取住户自有可回收物？
2. 定向交付与来源不明的公区物品怎样区分？
3. 允许放在哪里、最长放多久、谁有权取走？
4. 这项收入对人员稳定是否真的有意义？是否会造成楼栋或班次之间的不公平？

### 假设五：匿名与实名双模式能兼顾使用率和闭环

**可能价值**：匿名提醒保持低门槛；实名上报只为确实想知道结果的人建立状态、结果和反馈闭环，不强迫所有居民登录。

**可能反证**：匿名信息质量低或容易滥用；实名事项会让居民期待客服式时限；两种模式使物业操作和解释更复杂。

**要问：**

1. 匿名提醒在物业看来最低需要哪些现场信息，哪些内容没有也能处理？
2. 实名事项由管家、客服、保洁主管还是其他角色承接？
3. 哪些状态可以对实名住户说清楚：已收到、已安排、已完成、现场没发现？
4. 居民反馈“仍未解决”或“清洁后再次污染”后，谁继续处理，什么情况下转正式投诉？
5. 暂定复用小区企业微信成员身份后，企业微信由谁管理、目录是否及时移除已搬离住户并区分居民与物业人员、能提供哪些必要字段？谁确实需要看到、保存多久？业委会是否只看去身份化事实？
6. 实名是否会被误解为优先处理？怎样明确两种模式不影响待办优先级？

### 假设六：现有“透明社区”可能只需要一个更轻的入口

**可能价值**：楼层二维码和两步上报可以成为现有系统的前端入口，不必新建后台；日常高频小事也可能提高居民对既有平台的使用习惯。

**可能反证**：低使用率来自处理能力或信任，而不是入口；对接成本高于独立试验；现有厂商不支持匿名与实名双模式。

**要问：**

1. “透明社区”当前有哪些入口、使用人数和处理角色？居民通常在哪一步退出？
2. 物业希望提高它的使用率吗，还是目前使用率已经符合定位？
3. 能否让二维码直接带出楼栋楼层并缩短表单？
4. 能否同时支持匿名只提醒与实名可追踪，且不重复建立两套待办？
5. 如果系统能力具备，问题是否仍卡在物业承接流程和人员安排？

### 假设七：新增系统成本可能大于全部收益

**可能价值**：如果每天操作极少、规则清楚，工具可能用很小成本补上事实链。

**可能反证**：新增渠道、培训、二维码维护、例外处理、身份保护和居民预期管理的成本，远大于减少的争议或空跑。

**要问：**

1. 哪个角色每天会增加什么操作，各需要多少时间？
2. 谁负责二维码损坏、错误位置、现场没发现、重复污染和实名反馈？
3. 什么结果出现时物业愿意继续，什么结果出现时应立即停止？

## 三、建议的 45 分钟访谈顺序

1. **前 5 分钟：说明边界。** 这不是上线提案，业委会只是原则支持继续了解；今天的目标是找到或否定物业侧的真实问题。
2. **第 5—20 分钟：请物业复盘一条真实事项。** 从居民在群里发消息开始，一直问到一线处理、结果确认和争议处理，不先展示完整方案。
3. **第 20—30 分钟：验证七组假设。** 优先问服务结果、保洁履约、定向回收和现有系统；主动邀请对方指出项目没有价值的地方。
4. **第 30—38 分钟：再展示最小方案。** 说明楼层码、匿名提醒、暂定使用企业微信认证的实名追踪、保洁完成记录和去身份化监督；明确当前原型只做了匿名最短流程。
5. **第 38—43 分钟：共同算投入产出。** 谁多做什么，可能减少什么，哪些风险必须先解决。
6. **最后 2 分钟：只请求下一步。** 如问题成立，请物业安排保洁主管与两三名一线保洁继续访谈；不要求当场同意试点。

## 五、只有满足这些条件才继续谈试用

- 物业能说出至少一个自己愿意改善的具体问题，而不只是礼貌支持；
- 物业同意让保洁主管和一线保洁直接表达意见；
- 匿名与实名事项分别由谁承接、实名身份谁可见，能够写成清楚规则；
- 一线保洁认为完成记录能保护劳动或改善回收收入，且操作负担可接受；
- 现有工具无法以更低成本完成同样目标，或者物业愿意优先改造现有入口；
- 试用有明确退出条件，不把新增操作永久压给一线人员。
