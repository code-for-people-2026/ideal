# “公区随手拍”用户体验与用户故事

> 这是一份面向普通读者的试用说明：它回答“用户可以拿它做什么、通常怎么做，以及哪些地方目前还不能确定”。
>
> 研究对象仅限深圳市四格互联信息技术有限公司的“公区随手拍”。访问与核实日期：2026-08-13。

## 一眼看懂：用户可以用它做什么

1. 在公共区域扫描二维码，快速进入报事入口，不必先找物业电话；2021 年官方演示称扫码“无需注册、自动带出位置”。
2. 选择报事类型，再用文字、录音或图片说明问题；官方演示表单还包括项目、位置、服务流程、服务分类和联系方式。
3. 报修公共设施、反馈卫生或安全隐患、提出投诉建议；具体入口和名称会随客户部署而变化。
4. 提交后形成一张工单，由工作人员接单、派单和处理；处理结果再通知用户。
5. 从“我的报事记录”回看自己提交过的事项，并进入某条记录查看详情和问题轨迹。
6. 在事项处理后评分和写评价；官方演示展示了五星与文字评价。
7. 患者或工作人员也可以在医院等场所扫码提交公区卫生、安全隐患需求，而工作人员从移动工作平台处理。

以上能力分别由[四格互联 2021 年官方演示视频](https://www.segiuhome.com/static/upload/other/20210923/1632361061693174.mp4)、[当前医院后勤方案页](https://www.segiuhome.com/ywfnljjfa/1892.html)和[深圳新东升医院项目公告](https://www.segiuhome.com/companynews/1772.html)支持。后两者属于厂商陈述；视频界面属于官方演示，不等于每个客户在 2026 年看到的同一版本。

## 先说明产品形态

“公区随手拍”更像一个可配置的 **B2B 区域报事模块**，而不是所有人下载后界面都一样的统一 App。

四格互联当前在医院方案中把它与中央运送、综合巡查等模块并列；城奥大厦案例则称客户同时使用公区随手拍、巡查、会议室和客户服务功能。因此，不同小区、写字楼或医院可以配置不同入口、表单和处理流程。[当前方案页](https://www.segiuhome.com/ywfnljjfa/1892.html)、[城奥大厦案例](https://www.segiuhome.com/companynews/1743.html)（厂商陈述）。

这也解释了为什么用户当前试用所见，可能与 2021 年官方演示不同：两者不一定互相矛盾，更可能是部署版本或客户配置不同。不过，公开材料没有披露配置后台，下面不会把“可能可配置”当作已经证实的具体能力。

## 用户故事与实际路径

### 故事 1：居民在现场快速报修

**作为居民，我可以在发现问题的地方扫码报事，以便少填位置、快速告诉物业哪里坏了。**

实际路径：找到现场二维码 → 微信扫码进入 → 确认或选择项目、位置 → 选择服务流程和分类 → 写文字、录音或上传图片 → 填联系人和电话 → 提交。

![官方演示中的二维码入口](./assets/公区随手拍/01-二维码入口-60s.png)

*2021 官方演示直接写明“无需注册、自动带出位置”；手机首页可见扫码与多个报事入口。[视频 01:00](https://www.segiuhome.com/static/upload/other/20210923/1632361061693174.mp4#t=60)*

需要留意：官方一边说“自动带出位置”，演示表单一边仍显示“所在项目、所在位置”的选择项。公开画面没有展示预填后的具体值，也没有展示用户如何纠错位置。

### 故事 2：居民按问题类型进入服务

**作为居民，我可以先选择投诉、公共报修或室内报修等入口，以便进入适合当前问题的报事路径。**

实际路径：打开服务首页 → 点击一个快捷入口 → 填写或确认该事项所需信息 → 提交。

2021 官方演示首页直接可见“室内报修、公共报修、投诉建议、问题反馈”；用户本次试用还观察到来访登记、安保服务、清洁/绿化和物品放行等入口。后四项未在本次找到的“公区随手拍”官方公开页面或演示中逐项出现，因此只能记为**用户试用观察**，不能写成所有部署的标准菜单。[视频 01:00](https://www.segiuhome.com/static/upload/other/20210923/1632361061693174.mp4#t=60)

### 故事 3：居民用多种方式描述问题

**作为居民，我可以输入文字、按住录音或上传现场图片，以便在不方便打字时也能说清楚问题。**

实际路径：进入上报信息页 → 补充分类与联系信息 → 选择文字、录音和图片中的适用方式 → 点击提交。

![官方演示中的上报表单](./assets/公区随手拍/02-上报表单-66s.png)

*2021 官方演示可见所在项目、所在位置、服务流程、服务分类、联系人、联系电话、内容、上传录音、上传图片和提交按钮。[视频 01:06](https://www.segiuhome.com/static/upload/other/20210923/1632361061693174.mp4#t=66)*

演示中的服务流程、服务分类、联系人、联系电话和内容带有必填标记。图片数量、录音时长、手机号是否校验，以及各快捷入口是否显示不同字段，公开证据没有回答。

### 故事 4：居民回看进度和处理轨迹

**作为居民，我可以从“我的报事记录”找到过去提交的事项，以便知道有没有人处理、目前走到哪一步。**

实际路径：打开首页 → 点击“我的报事记录” → 选择一条事项 → 查看服务详情与问题轨迹 → 处理后评价。

![官方演示中的服务详情和问题轨迹](./assets/公区随手拍/03-服务详情与轨迹-74s.png)

*2021 官方演示的详情页可见工单号、提单人、地址、申请时间、项目、描述、房屋地址、紧急程度、“问题轨迹”和评价入口。[视频 01:14](https://www.segiuhome.com/static/upload/other/20210923/1632361061693174.mp4#t=74)*

公开视频没有单独展示“我的报事记录”的列表页，所以尚不能确认列表卡片会显示哪些字段、能否筛选、能否补充或撤回，也不能确认所有内部流转是否都对用户可见。

### 故事 5：患者或医院工作人员提交后勤需求

**作为患者或医院工作人员，我可以扫描场所二维码提交公区卫生或安全隐患，以便让后勤团队跟进。**

实际路径：扫描医院内二维码 → 提交卫生或安全隐患需求 → 后台跟进 → 员工在移动工作平台处理。

这条路径来自四格互联的[深圳新东升医院后勤平台建设公告](https://www.segiuhome.com/companynews/1772.html)。公告写的是“建成后的系统”，可以证明厂商的部署方案，不能证明项目已经上线或实际处理时效。

### 故事 6：处理人员接单并形成闭环

**作为处理人员，我可以接单、被派单、更新处理结果并通知用户，以便让报事不只停留在提交。**

实际路径：收到工单 → 接单或由管理方派单 → 处理 → 通知用户 → 等待评价。

官方演示画出“提交 → 接单 → 派单 → 处理 → 通知 → 评价”的流程，并称节点可追溯、管理者可查看和调度。[视频 01:34–01:43](https://www.segiuhome.com/static/upload/other/20210923/1632361061693174.mp4#t=94) 但视频没有展示工作人员实际操作界面，也没有说明派单是自动还是人工。

## 两个未知项的直接回答

### 1. 二维码是否按事件类别区分？会预填什么？

**公开证据无法确认存在“每类事件一个二维码”。** 官方演示展示的是贴在物理地点的二维码，扫码后首页仍有多个报事类型；官网也强调“物理网格区域定点”。因此，现有证据更支持二维码至少用于绑定**地点/空间**，而不是直接证明它绑定某一种事件。

可以确认的预填只有厂商所说的“位置”。但公开材料没有披露二维码实际包含项目 ID、楼栋、楼层、房间还是点位，也没有展示预填后的值。演示表单仍让用户选择“所在项目”和“所在位置”，所以不能进一步断言这两个字段都会被完整填好。

同一表单中的“服务流程”和“服务分类”仍显示为待选择，故也没有证据证明扫码会预填事件类型。最稳妥的结论是：**官方设计意图是用二维码缩小或带出位置；是否一类一码、具体预填哪些字段，要针对用户试用的那个客户部署继续实测。**

### 2. “我的报事记录”里能查看什么？

**可以确认的是：存在“我的报事记录”入口，并且某条事项的详情可展示工单信息和问题轨迹。** 2021 演示详情页可见工单号、提单人、地址、申请时间、项目、描述、房屋地址、紧急程度、问题轨迹，以及处理后的评价入口。

**不能确认的是记录列表本身。** 公开视频没有展示列表卡片、筛选条件、照片、完整状态名、处理人、预计完成时间、撤回/补充/重开等功能，也没有解释免注册用户如何找回自己的记录。因此，这些不能从“我的报事记录”这个名称推断出来。

## 一次完整体验，可以先这样理解

如果把证据已经覆盖的部分连起来，它最像下面这条路：

> 在问题现场扫码 → 系统尝试识别位置 → 用户选择类别并用文字、录音或图片提交 → 后台形成工单 → 工作人员接单/派单/处理 → 用户收到通知 → 从记录里看详情与轨迹 → 评价。

其中，“系统尝试识别位置”和“形成闭环”是官方明确设计；每个客户的首页入口、表单字段、身份验证和派单规则则可能不同。

## 证据怎么读

- **用户试用观察：** 本次需求方实际看到的入口和体验，适合描述该次部署，但不能自动推广到所有客户。
- **官方视频直接观察：** 2021 年四格互联演示画面中能直接看见的界面和路径；可证明演示版本，不代表 2026 年统一现状。
- **厂商陈述：** 官网方案和项目公告中的能力说明；可证明产品定位或建设计划，不等于独立验证过的实际效果。
- **推断：** 由多条证据合起来得到的合理解释，例如“更像可配置 B2B 模块”；本文均明确标出，不把推断当事实。
- **证据缺口：** 公开材料没有回答的地方；本文没有借用其他同名“随手拍”产品补齐。

## 仍值得补一次真实试用

- 分别扫不同地点、不同类别的二维码，对比链接参数与首屏预填值。
- 逐个点击七类快捷入口，记录字段、必填项和提交后的状态是否不同。
- 提交一条无敏感内容的测试事项，截图“我的报事记录”列表、详情和每次状态变化。
- 验证是否必须登录或验证手机号，以及换手机后能否找回记录。
- 验证能否补充图片、撤回、催办、重开，以及处理结果是否包含现场照片。
