# Harness v2 提示词 A/B：独立设计审计

日期：2026-08-27
审计范围：现有评测协议、6 份第一阶段原始响应及其评分
数据边界：本审计未调用外部 API、未上传或读取视频资产；只使用仓库内 Markdown/JSON 记录

## 结论先行

本轮可以进行一个低成本、方向性的配对 A/B：固定 `qwen3.5-omni-plus-2026-03-15`、视频文件、采样率、温度、输出上限及其余调用参数，只将原统一提示词替换为本文的 Harness v2，分别重跑视频2和视频3。A 组使用已经归档的原始响应，B 组新增两次调用。

这项实验能回答：“在这两个已出现典型证据错误的单元中，加入证据核查 harness 后，单次输出是否改善？”它不能证明模型已稳定改善，因为 A、B 都只有一次采样，而且不是同期随机重复。若 B 达到本文的强成功门槛，再追加独立重复运行测随机性。

Harness v2 没有写入三段视频的正确题面、答案、具体变量、数字、选项或已知错误的具体内容；也没有提及视频编号或页面标题。它只加入通用的观察顺序、证据门槛和提交前审计规则。运行程序必须只提取本文“B 组可执行提示词”代码块，不得把本文其他章节拼入模型输入。

## 1. 设计依据

原协议已经正确规定：第一阶段只记录题面、口述、书写、手势与时间关系，不解题、不评价，并使用统一的 24 分量表和致命错误门槛。[两阶段评测规范](../protocol/两阶段评测规范.md)；[原统一提示词](../protocol/第一阶段统一提示词.md)

六份基线响应显示，原则性禁止语句本身不足以约束一次性自由生成。主要失效模式为：

1. **视觉题面被替换、遗漏或补全**：有的关键数学字符被改变，有的初始可见内容整体遗漏，有的初始内容被重构成视频中不存在的内容；错误仍被赋予很高置信度。[视频1 Flash 评分](../formal/video-01/qwen3.5-omni-flash-2026-03-15/第一阶段评分.md)；[视频3 Plus 评分](../formal/video-03/qwen3.5-omni-plus-2026-03-15/第一阶段评分.md)
2. **来源与时间状态混淆**：模型会把印刷、视频开始前已经存在的手写、视频内新增手写混在一起；“手写”这一二元标签无法表达“开始前已有”和“本次新写”的区别。[视频2 Plus 评分](../formal/video-02/qwen3.5-omni-plus-2026-03-15/第一阶段评分.md)；[视频3 Flash 评分](../formal/video-03/qwen3.5-omni-flash-2026-03-15/第一阶段评分.md)
3. **未发生的动作被写成事实**：口头表达某个选择，不足以证明画面中发生了对应的圈选或标记；两款模型都出现了这类视觉动作虚构。[视频2 Flash 原始响应](../formal/video-02/qwen3.5-omni-flash-2026-03-15/第一阶段原始响应.md)；[视频2 Plus 原始响应](../formal/video-02/qwen3.5-omni-plus-2026-03-15/第一阶段原始响应.md)
4. **口述与书写互相修正**：模型会用更合理的书面条件补足口头理由，或把语音中的意图当作已发生的视觉事实，最终证据包比学生实际表达更完整。[视频3 Flash 评分](../formal/video-03/qwen3.5-omni-flash-2026-03-15/第一阶段评分.md)；[视频3 Plus 评分](../formal/video-03/qwen3.5-omni-plus-2026-03-15/第一阶段评分.md)
5. **置信度失校准**：Flash 常把大量条目统一标为 100%，Plus 在视频3几乎统一标为 98%；高细节量与高置信度并没有防止关键事实错误。[视频1 Flash 原始响应](../formal/video-01/qwen3.5-omni-flash-2026-03-15/第一阶段原始响应.md)；[视频3 Plus 原始响应](../formal/video-03/qwen3.5-omni-plus-2026-03-15/第一阶段原始响应.md)

因此，B 组不能只增加一句“请仔细检查”。它需要把输出条件改成可验证的证据门槛：初始状态单独盘点、视觉与语音隔离、动作需要前后状态、所有关键事实必须能追溯到时间和模态、提交前主动删除无支持断言。

## 2. 实验问题与假设

### 2.1 主要问题

在同一模型快照、同一视频字节和同一推理参数下，仅替换提示词，Harness v2 是否能：

- 减少题面关键内容的遗漏、替换和臆造；
- 正确区分印刷、开始前已有手写和视频内新增手写；
- 不再把未观察到的标记、圈选、擦除或指向写成已发生；
- 忠实保留口述与书写的不一致，不用一个模态修复另一个模态；
- 让错误或单帧难辨的关键事实获得较低置信度或候选读法；
- 在减少幻觉的同时，不显著损失口述覆盖和关键书写事件召回。

### 2.2 预注册假设

- **H1，致命错误**：B 组两个单元均不出现第一阶段致命错误。
- **H2，事实精度**：B 组的题面关键原子准确率、来源状态准确率、视觉动作精确率均高于各自 A 组。
- **H3，跨模态纪律**：B 组没有“只由另一模态支持，却被当作当前模态事实”的关键断言。
- **H4，校准**：B 组不存在置信度不低于 90% 的关键错误；整体 Brier 分数低于 A 组。
- **H5，覆盖不退化**：B 组口述覆盖、时间定位和真实书写事件召回均不比 A 组下降超过 1 个量表分。

## 3. 实验矩阵

本次第一轮只使用两个最有诊断价值的 Plus 单元：

| 配对 | 视频 | 模型 | A 组 | B 组 |
|---|---|---|---|---|
| P1 | 视频2 | `qwen3.5-omni-plus-2026-03-15` | 已归档原提示词响应 | Harness v2 新调用 |
| P2 | 视频3 | `qwen3.5-omni-plus-2026-03-15` | 已归档原提示词响应 | Harness v2 新调用 |

A 组原始响应分别见：[P1 A](../formal/video-02/qwen3.5-omni-plus-2026-03-15/第一阶段原始响应.md)、[P2 A](../formal/video-03/qwen3.5-omni-plus-2026-03-15/第一阶段原始响应.md)。

选择这两个单元不是因为已把答案泄露给 B 组，而是因为它们覆盖了不同的证据失效类型。视频或已知差异只用于实验选择和事后盲评，不进入提示词。

### 3.1 固定变量

以下参数必须与对应 A 组保持一致：

| 变量 | 固定值/规则 |

| 模型 | `qwen3.5-omni-plus-2026-03-15` 固定快照，不换别名 |
| 视频 | 使用对应 A 组相同本地文件，并在调用前核对同一 SHA-256 |
| 视频采样 | `fps=1.0` |
| 温度 | `0.1` |
| 最大输出 | `8192` tokens |
| 输出模态 | 仅文本 |
| Web Search | 关闭 |
| API 端点与文件上传方式 | 与 A 组相同 |
| 视频标题、BVID、链接、人工参考答案 | 均不进入模型消息 |
| 上下文隔离 | 不提供 A 组输出、其他模型输出、评分或第二阶段数学分析 |

这些调用参数由两份 A 组运行元数据确认：[视频2运行元数据](../formal/video-02/qwen3.5-omni-plus-2026-03-15/run-metadata.json)、[视频3运行元数据](../formal/video-03/qwen3.5-omni-plus-2026-03-15/run-metadata.json)。

### 3.2 唯一自变量

唯一计划改变的变量是文本提示词：

- A：原统一提示词；
- B：下节 Harness v2 完整提示词。

提示词变长会自然增加少量文本输入 token，也可能改变输出长度；这是处理变量的一部分，不应通过缩短视频、改 fps、改温度或改 `max_tokens` 来抵消。

### 3.3 设计限制

本轮使用历史 A 组而非同期重跑 A，无法完全排除服务端实现漂移和模型随机性。即使模型 ID 是固定快照，也只能把结果称为“配对的提示词修订对照”，不能据此估计稳定提升率。若第一轮成功，严格确认应至少对每个视频执行 `A×3 + B×3`，交错顺序并随机化 A/B 先后。

## 4. B 组提示词泄露审计

### 4.1 禁止进入 B 组输入的内容

运行前对最终请求体进行自动或人工检查，确保不存在：

- 视频编号、BVID、页面标题或链接；
- 三段视频的任何具体题面字符、变量、数字、表达式、选项或答案；
- 已知错误的具体更正值；
- “本视频中模型曾经误认了……”之类的定向提示；
- A 组响应、评分、第二阶段分析或人工核验结论；
- 其他视频模型的输出。

### 4.2 允许出现的通用规则

以下内容不构成泄露：要求区分信息来源；要求以时间戳支持动作；要求保留候选读法；要求不把口述和书写互相修正；要求为高置信度设置普适证据门槛。这些规则不包含任何目标视频的事实答案。

### 4.3 审计结论

下方可执行提示词通过静态泄露检查：没有出现任何目标视频特有的题面、答案、人物、选项、已知动作或已知错误内容。为防止运行时误拼接，调用脚本应把提示词单独保存并记录 SHA-256；模型消息只包含该提示词与视频，不包含本报告其余文字。

## 5. B 组可执行提示词

以下代码块是 B 组唯一可执行的文本提示词。

```text
你是一名严格的视频证据记录员。请完整观看并聆听所提供的“学生讲解数学题”视频。

本阶段只测试你是否能忠实识别视频中的题面、口述、书写变化、手势指向及其时间关系。不要解题，不要判断学生对错，不要评价学生能力，不要给教学建议。即使某种题目或解法看起来熟悉，也不得用数学常识、后续答案或语音内容修正视觉字符。

请在内部严格依次完成下面六轮核查，但不要输出内部推理过程；只输出最后的证据包。

第一轮：初始画面状态
1. 确定学生第一次在纸面新增笔迹之前的基准时刻；无法唯一确定时给出候选时间范围。
2. 盘点基准时刻所有承载信息的画面区域，给每个区域分配R01、R02……
3. 来源状态只能使用：印刷、视频开始前已存在的手写、视频内新增手写、无法确认。不得把“手写”自动等同于“学生在本视频中写下”。

第二轮：视觉题面逐字符核对
1. 视觉抄录只依据画面，不用口述补全。逐项核对底数、指数、括号、分数线、省略号、正负号和运算符。
2. 只有实际看清的字符才能写入精确内容。局部清楚时只抄局部；不能完整确认时列出候选读法，不得选择数学上更合理的一项。
3. 学生口头提到的例题、第一题、下一问或图形，都必须映射到一个已盘点区域；映射不到时列为“口头提及但视觉内容未确认”，不得自行重建内容。

第三轮：口述原貌
1. 口述记录只依据音频，保留停顿、重复、口误、自我修正和未说完的话。
2. 不得用画面笔迹把不完整或不合理的口述改写成完整理由；听不清时保留原声片段的候选听法。

第四轮：书写与动作增量
1. 一项内容只有同时给出写入前状态、动作时间和写入后状态，才可标记为“视频内新增、修改、划掉或擦除”。
2. 圈选、打勾、擦除、划线、指向等短暂动作，必须在画面中直接看到动作过程及对象；口头说要选择、修改或指向，不能证明视觉动作已经发生。
3. 如果只看到最终状态而未看到形成过程，写“最终状态可见，形成动作无法确认”。如果只听到意图，写“仅听到，未确认画面动作”。

第五轮：跨模态对齐
1. 为每条事实分别标记“听到”“看到”或“视听对应”。同一行中必须明确哪部分来自声音、哪部分来自画面。
2. 口述与书写不一致时并列记录两者，不得让一方替另一方纠错，不得补写学生未表达的理由、条件或中间步骤。
3. “这里、这个、前面”等指代只有在当时画面对象唯一且动作可见时才绑定；否则列候选对象或写无法确认。

第六轮：提交前反证审计
逐条检查准备输出的关键事实：
1. 是否有明确时间戳、画面区域和证据模态；没有则删除或改为无法确认。
2. 是否把开始前已有内容写成视频内新增；若是则纠正来源状态。
3. 是否把口头意图写成画面动作，或把书面条件写成口头理由；若是则拆分并降级。
4. 是否存在学生提及但尚未映射的题目、例题、小问或图形区域；若有，必须列入遗漏/待核项。
5. 最终概括是否加入证据表中没有的新事实；若有则删除。

置信度纪律：
- 每条关键事实给出0至100%的置信度。
- 静态关键文字只有在至少两个清晰时刻能独立看清时，才可高于90%。
- 短暂动作只有看到动作前、动作过程和动作后状态时，才可高于90%。
- 只有单帧、局部遮挡、字符相似、来源难分或跨模态冲突时，最高90%，并必须说明原因或候选读法。
- 不得因为内容在数学上连贯、与最终答案相符或与另一模态一致而提高当前模态的置信度。

输出格式：

### 1. 媒体可用性
- 总时长：
- 画面连续性：
- 声音连续性：
- 遮挡、模糊、噪声或快速动作：
- 第一次新增笔迹前的基准时刻或候选范围：

### 2. 题面与初始状态逐项抄录
| 编号 | 区域编号 | 精确内容 | 来源状态 | 首次清晰时间 | 第二个独立清晰时间 | 画面位置 | 置信度 | 候选读法/无法确认 |
|---|---|---|---|---|---|---|---|---|

### 3. 带时间戳的口述记录
| 时间范围 | 尽量贴近原话的口述 | 听不清处/候选听法 | 置信度 |
|---|---|---|---|

### 4. 视听联合时间线
| 时间范围 | 学生说了什么 | 动作前可见状态 | 直接观察到的动作 | 动作后可见状态 | 手势或指向对象 | 对应关系 | 证据类型 | 置信度 |
|---|---|---|---|---|---|---|---|---|

### 5. 过程异常、不确定项与覆盖审计
- 逐项列出口述与书写不一致；
- 逐项列出题面、声音、来源和指向的候选解释；
- 列出每个初始区域是否已进入题面表；
- 列出学生口头提及的每个题目、例题、小问或图形是否已映射；
- 列出只听到意图但没有确认画面动作的事件；
- 列出提交前被降级为“无法确认”的关键事实。

### 6. 证据索引
| 证据编号 | 时间戳 | 区域编号 | 听到/看到/视听对应 | 原始内容 | 置信度 |
|---|---|---|---|---|---|

证据编号从E01开始。只记录事实，不写数学结论。最后用不超过80个汉字概括：视频中学生讲解了哪些视觉上可确认的题目、完成了哪些可观察的书写或指示动作。概括只能引用已经列出的证据编号，不得加入新事实，也不得评价数学正确性。
```

## 6. 盲评方案

### 6.1 盲评材料隔离

每个视频形成 A、B 两个候选响应。评分前：

1. 去除运行时间、文件夹名、prompt 名称、token 与费用等组别元数据；
2. 为候选响应随机分配无语义编号，例如 `C7F2`、`K4M9`；
3. 组别映射由独立文件保存，在原子事实表和评分表冻结前不揭盲；
4. 评分者只获得候选响应、相同的本地参考证据和锁定后的评分手册；
5. 先逐条判原子事实，再计算总分，不先给整体印象分。

提示词会改变输出列结构和写作风格，因此评分者可能推测出组别，严格双盲并不现实。降低偏差的关键不是假装完全盲，而是隐藏标签、预注册指标、以原子事实自动汇总，并在揭盲前冻结判定。

### 6.2 原子事实类型

把每份响应拆成以下原子，不允许把一整段只判一次：

| 类型 | 代码 | 一个原子的定义 |
|---|---|---|
| 题面字符/结构 | `P` | 一个数字、变量、指数、括号、分数关系、运算符或关键自然语言条件 |
| 区域来源状态 | `S` | 一个区域在基准时刻属于印刷、已有手写、新增手写或无法确认 |
| 口述 | `O` | 一个有时间范围的独立口头命题、停顿、更正或口误 |
| 书写增量 | `W` | 一次有前后状态的新增、修改、划掉或擦除 |
| 短暂视觉动作 | `A` | 一次圈选、打勾、指向、连线或其他瞬时动作 |
| 跨模态对应 | `X` | 一条声音内容与一个画面对象的对应关系 |
| 理由/条件归属 | `R` | 某个理由或条件究竟被说出、写出、两者都有，还是模型推断 |

每个模型断言记录：候选编号、事实类型、原文、时间戳、区域、模型置信度、参考真值 `1/0/无法评分`、错误类型。参考中无法可靠判定的原子不计准确率，但要计模型是否合理弃权。

### 6.3 主要指标

| 指标 | 计算 | 目的 |
|---|---|---|
| 致命错误数 | 按原协议五项规则逐单元计数 | 第一优先级，不能被总分抵消 |
| 题面关键原子准确率 `P-Acc` | 正确关键P原子 / 已断言关键P原子 | 检测字符替换和臆造 |
| 题面覆盖率 `P-Recall` | 被正确提取的参考关键P原子 / 参考关键P原子 | 检测整段或关键项遗漏 |
| 来源状态准确率 `S-Acc` | 正确S原子 / 可评分S原子 | 检测印刷、已有手写、新增手写混淆 |
| 动作精确率 `A-Precision` | 真实A原子 / 模型断言A原子 | 检测未发生动作；无动作断言时记为适用且精确率1 |
| 动作召回率 `A-Recall` | 被提取的真实关键A原子 / 参考关键A原子 | 防止模型通过不写动作获得虚假改善 |
| 书写召回率 `W-Recall` | 被提取的真实关键W原子 / 参考关键W原子 | 防止过度弃权 |
| 跨模态污染数 `X-Contam` | 仅由另一模态支持却被写成本模态事实的关键断言数 | 检测口述与书写互相修正 |
| 无依据理由数 `R-Fabricated` | 没有口述或书写支持却归因给学生的关键理由数 | 检测替学生补逻辑 |
| 高置信度关键错误 `HC90` | 错误且置信度≥90%的关键原子数 | 检测置信度失校准 |
| Brier分数 | 对可评分原子计算 `mean((p-y)^2)`，`p=置信度/100` | 比单看平均置信度更稳健，越低越好 |
| 原24分量表 | 按既有六维评分 | 与第一轮正式报告保持可比 |

`P-Acc` 与 `P-Recall` 必须同时报告：只提高精确率而大幅漏抄不算成功。`A-Precision` 与 `A-Recall`、`W-Recall` 同理。

### 6.4 五类定向错误标签

为便于直接回答本次问题，另锁定五个错误标签：

- `E-OMIT`：关键题面、例题、小问或画面区域遗漏；
- `E-SOURCE`：印刷/已有手写/新增手写来源错误；
- `E-ACTION`：断言未发生的动作，或把口头意图当视觉动作；
- `E-CROSS`：用口述修复书写，或用书写修复口述/理由；
- `E-CONF`：错误关键事实仍给不低于90%的置信度，或宣称无不确定项。

这些标签按事实判定，不因最终数学结论是否碰巧正确而减轻。

## 7. 成功门槛

### 7.1 硬门槛

两个 B 单元必须同时满足：

1. 致命错误数为0；
2. `R-Fabricated=0`；
3. `X-Contam=0`；
4. `HC90=0`；
5. 未出现新的、A 组没有的关键题面替换或整段臆造；
6. 模型没有越界解题、判断学生对错或给教学建议。

任一硬门槛失败，即判定“当前 harness 未通过”，即使24分总分上升也不例外。

### 7.2 最低成功

在全部硬门槛通过的前提下，还需：

- 两个 B 单元平均24分相对 A 组提高至少3分；
- 每个 B 单元的24分不低于自己的 A 组；
- 每个 B 单元 `S-Acc` 与 `A-Precision` 均高于 A 组；
- `P-Acc`、`P-Recall`、`A-Recall`、`W-Recall` 中任何一项不得相对 A 组下降超过5个百分点；
- 原量表的“口述准确与覆盖”“时间定位”任一维度不得下降超过1分。

### 7.3 强成功

在最低成功基础上：

- 两个 B 单元都达到至少21/24；
- 两个单元的 `E-OMIT`、`E-SOURCE`、`E-ACTION`、`E-CROSS`、`E-CONF` 均为0；
- 两个单元的关键 `P-Acc`、`S-Acc`、`A-Precision` 均为100%；
- B 组平均 Brier 分数至少比 A 组下降30%，且真实关键书写、口述与动作的覆盖没有明显减少。

由于样本只有两个且每格一次，达到强成功也只代表“值得进入重复性测试”，不能宣称已证明普遍有效。

## 8. 执行与封存清单

### 调用前

- [ ] 核对两个输入视频的 SHA-256 与 A 组相同；
- [ ] 锁定模型快照、fps、温度、max tokens、输出模态和 Web Search；
- [ ] 从第5节代码块生成独立 prompt 文件并记录 SHA-256；
- [ ] 检查最终模型消息不含标题、链接、BVID、正确题面、答案、A 输出或评分；
- [ ] 保留原始响应，不做人工润色或格式修复。

### 调用后、评分前

- [ ] 保存请求参数、usage、时延与费用；
- [ ] 生成匿名候选编号并封存 A/B 映射；
- [ ] 用同一参考事实表拆解 A、B 原子；
- [ ] 在揭盲前完成所有真值、错误标签、24分评分和致命错误判定；
- [ ] 计算预注册指标，不临时更换成功门槛。

### 揭盲后

- [ ] 分视频报告 A→B 的改善、退化与新增错误；
- [ ] 单独列出 prompt token、输出 token、时延和成本变化；
- [ ] 明确结果属于单次配对、不能代表稳定性；
- [ ] 只有达到强成功才进入重复运行，不把继续调 prompt 当作同一次预注册实验。

## 9. 解释边界

Harness v2 主要提高的是**证据纪律和可审计性**，不能保证模型看清原始分辨率中本来不可辨的字符。一个理想变化可能是模型从“高置信度写错”变成“低置信度候选或无法确认”；这属于安全性改善，即使表面信息量减少。

反过来，如果 B 组只增加了更长的检查表，却仍高置信度重复同一虚构内容，说明单模型自审计无法纠正其感知先验。下一步应改为真正的多阶段 harness（独立初始帧识别、语音转写、书写增量检测和反证审计分别产出后再合并），而不是继续堆叠同一条 prompt。
